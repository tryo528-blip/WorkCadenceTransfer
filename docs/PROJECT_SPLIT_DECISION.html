Operational safety

P2 결정

삭제

성공 확인 후에만

PC가 완전수신·해시검증·원자 저장을 끝낸 뒤, 단말·제출 ID·digest가 모두 맞는 인증된 READY ACK를 돌려준 경우에만 모바일 키와 사진을 삭제합니다.

오작동

정본은 한 건만

빠른 다중 탭, 재시도, 앱 crash와 ACK 유실에서도 같은 제출은 같은 정본과 ACK를 재사용합니다.

전송방식

Foreground only

백그라운드 자동전송은 만들지 않습니다. 사용자는 전송 화면을 열어 진행률과 성공을 직접 확인합니다.

Batch

메모 또는 사진 1~5장

메모만, 사진만 1~5장, 메모+사진 1~5장을 허용하고 빈 제출과 6장은 네트워크 전에 거부합니다.

Optional later

P3는 무엇인가?

P3는 지금 없어도 안전한 첫 버전을 사용할 수 있는 편의기능입니다. 결함이 아니라 “나중에 필요하면 추가”할 항목입니다. 처음부터 넣으면 권한·네트워크·시험 범위가 커져 오히려 출시가 늦고 불안정해집니다.

보류

자동 PC 검색

Bonjour 대신 QR 또는 수동으로 PC를 등록합니다.

제외 확정

백그라운드·push

Foreground 전송으로 결정했으므로 첫 버전에 넣지 않습니다.

금지

Cloud·후속 시스템 직접연결

외부 업무데이터 서버와 후속 시스템 API·DB 직접 연결은 모두 금지합니다.

보류

OCR·자동분류·얼굴판별

촬영·전송의 핵심 기능이 아니며 개인정보 처리도 늘립니다.

보류

끊긴 지점부터 이어 보내기

첫 버전은 1~5장 제출 묶음을 통째로 안전하게 재시도합니다. 일부 chunk만 이어 보내는 기능은 실제 불편이 확인될 때 검토합니다.

즉 P3를 안 만드는 이유빼먹은 것이 아니라 첫 버전을 작고 검증 가능하게 만들기 위해 의도적으로 미룬 것입니다.

사진 문제 두 가지를 모두 해결

필수 1

내가 직접 찍은 사진

  • 앱 카메라가 메모리/암호화 영역으로만 촬영
  • 갤러리 asset 생성 0
  • 전송 실패면 암호화 pending 유지
  • READY ACK 뒤 모바일 삭제
필수 2

상대가 카톡·문자로 준 사진

  • 상대방 앱 설치 불필요
  • 다운로드 대신 공유 → WorkCadenceTransfer
  • 공유 수신 화면은 즉시 암호화만 하고 본 앱에서 전송
  • 우리 갤러리 사본 생성 0
  • 원래 메신저·OS 사본은 프로젝트 통제 밖
촬영 대상과 허락은 사용자 운영사항앱이 사람·집안 판별이나 강제 동의 화면을 만들지는 않습니다. 기술적으로는 받은 데이터가 갤러리·로그·백업에 평문으로 남지 않게 처리합니다.

Plain-language security

BitLocker·ACL·DPAPI는 무슨 뜻인가?

BitLocker

PC나 SSD를 통째로 가져가도 Windows 잠금을 풀기 전에는 C: 드라이브 내용을 읽기 어렵게 하는 디스크 암호화입니다.

NTFS ACL

같은 PC의 다른 Windows 계정이 수신 폴더를 열거나 바꾸지 못하게 하는 폴더 출입권한입니다.

AES-GCM + DPAPI

사진과 메모 자체를 암호문으로 저장하고, 그 암호를 푸는 키도 receiver를 실행한 Windows 계정만 쓰도록 보호합니다.

형님이 할 일

기술 용어를 판단할 필요는 없습니다. 설치 단계에서 제가 실제 PC 설정과 다른 계정 접근 차단 시험을 확인해 PASS/FAIL로 보여드립니다.
