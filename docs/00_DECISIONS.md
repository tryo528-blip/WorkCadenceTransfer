# 확정 결정

상태: 승인된 구현 기준
기준일: 2026-08-14

## 프로젝트 경계

1. 현재 `WorkCadence`는 근태·메일·구인공고 프로젝트로 유지합니다.
2. 메모·사진 전송은 별도 `WorkCadenceTransfer` 프로젝트에서 구현합니다.
3. 두 프로젝트는 소스 의존성, application ID, 앱 이름, 아이콘, 데이터, 암호키와
   설치 산출물을 공유하지 않습니다.

## P1 확정

| 항목 | 확정 처리 |
| --- | --- |
| 앱 혼합 | 별도 프로젝트와 별도 앱으로 물리 분리 |
| 모바일 흔적 | 갤러리 미저장, 앱 전용 암호화 보관함, backup 제외 |
| 개인정보 운영 | 촬영 대상·허락·업무상 처리 판단은 운영자 책임. 앱은 평문 로그·썸네일·원본 파일명을 남기지 않음 |
| 인증·권한 | 단말별 등록키와 `transfer_upload` scope. 승인된 최소 권한 외 추가 금지 |
| 중복·부분파일 | 제출 ID·전체 해시로 멱등 처리하고 READY 전에는 성공 응답 금지 |
| 저장 경로 | Windows가 생성한 `recordId` UUID 경로만 사용하고 client ID·파일명·경로는 저장경로에 사용하지 않음 |

## P2 확정

1. 메모는 자유 텍스트이며 생성 시 서울 오늘 날짜를 `targetDate`로 붙입니다. 할일 상태,
   담당자와 반복 규칙을 만들지 않습니다.
2. Windows의 인증된 `READY_ACK` 전에는 모바일 원본을 삭제하지 않습니다.
3. 같은 제출이 반복되거나 앱이 오작동해도 Windows 정본은 한 건만 생성합니다.
4. 백그라운드 전송은 하지 않습니다. 사용자가 화면을 열어 둔 foreground에서 메모만,
   사진만 1~5장, 또는 메모+사진 1~5장을 한 번에 전송합니다.
5. 실패 시 갤러리가 아닌 모바일 암호화 보관함에 원본을 유지하고 명시적으로 재시도합니다.

허용 조합은 `메모만`, `사진 1~5장만`, `메모 + 사진 1~5장`입니다. 메모와 사진이 모두
비어 있으면 제출하지 않습니다.

## 사진 경로 두 가지

### 직접 촬영

- 앱 카메라가 촬영 결과를 메모리 또는 앱 전용 암호화 임시영역으로만 받습니다.
- Android MediaStore와 iOS PhotoKit 저장 API를 호출하지 않습니다.
- 전송 성공 뒤 암호키를 먼저 삭제하고 blob·썸네일·queue를 정리합니다.

### 카카오톡·문자 공유수신

- 상대방은 새 앱을 설치하지 않습니다.
- 사용자는 메시지 앱에서 사진을 다운로드하지 않고 `공유 → WorkCadenceTransfer`를
  선택합니다.
- Android Sharesheet 또는 iOS Share Extension으로 전달된 한정 URI만 읽습니다.
- 공유 수신 구성요소는 가져온 자료를 즉시 암호화할 뿐 네트워크 전송은 하지 않습니다.
  본 앱을 열고 미리보기 뒤 `PC로 보내기`를 눌러야 전송됩니다.
- WorkCadenceTransfer는 갤러리 사본을 만들지 않습니다.
- 원래 카카오톡·문자 대화와 provider cache는 이 프로젝트가 삭제할 수 없습니다.

## P3 설명

P3는 안전한 첫 버전에 없어도 되는 편의기능입니다. 결함을 뜻하지 않으며, 넣으면 공격면과
검수 범위가 커지므로 실제 필요가 확인된 뒤 별도 승인합니다.

- 자동 PC 검색·Bonjour: 첫 버전은 QR 또는 수동 등록 주소를 사용합니다.
- 백그라운드 자동전송·push: 첫 버전은 foreground 전송만 사용합니다.
- 외부 cloud relay·원격 링크: 외부 서버 금지 원칙 때문에 제외합니다.
- OCR·자동 문서분류·얼굴판별: 촬영·전송 목적에 필요하지 않아 제외합니다.
- 끊긴 사진만 이어 보내기: 첫 버전은 같은 제출 묶음 전체를 안전하게 다시 보냅니다.
- 전송 가속·병렬화: 5장 전송 속도가 실제로 부족할 때만 검토합니다.

즉 P3를 제외하는 것은 기능을 빼먹는 것이 아니라 첫 버전을 작고 검증 가능하게 만드는
의도적인 결정입니다.
